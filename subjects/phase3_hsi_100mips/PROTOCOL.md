# Registered 100 MIPS HSI arm — 2026-09-29

The user selected this arm before its first timing run. It replaces the proposed 16 MIPS HSI Phase 3 setting; the earlier Phase 1 16 MIPS data remain a separate pilot baseline. The selected STM32F407VG board uses the study-owned HSI overlay. The [STM32F407 DS8626 Rev. 12](https://www.st.com/resource/en/datasheet/stm32f407vg.pdf) bounds HSI accuracy at 25 °C to 16 MHz ±1%, so the **input oscillator** range is 15,840,000–16,160,000 Hz. The CPU model is an approximate coupling to that input, not a silicon execution guarantee. Renode 1.17.0 exposes integer `PerformanceInMips`; the [Renode time model](https://renode.readthedocs.io/en/latest/advanced/time_framework.html) is not instruction-cycle accurate. The direct fractional-MIPS probe is saved in `results/phase3_hsi_probe/fractional_mips_probe.json`.

## Fixed schedule and model settings

Use pinned Zephyr v4.3.0 commit `3568e1b6d5cdd51a6b964a2a1d6d29200fea2056`, STM32F4 Discovery, Renode 1.17.0, 1 µs quantum, 250 ms virtual observation step, and 90 s virtual cap. Nominal is SysTick/HSI 16,000,000 Hz and CPU throughput 100 MIPS. For seeds 0–99, draw `random.Random(seed).randint(15_840_000, 16_160_000)` **once** and apply the identical saved value to every eligible frozen suite. Set `systickFrequency = f` and `PerformanceInMips = floor(100*f/16_000_000 + 0.5)`, yielding 99, 100, or 101 MIPS. The integer quantization error and actual distinct MIPS states must be reported. Both exact oscillator endpoints are challenge runs outside the seeded-rate denominator. No other timer/peripheral frequency, interrupt hook, quantum, or firmware setting varies. The locked `plan.json` records exact inputs and hashes.

**Legality boundary:** each HSI input is inside the documented 25 °C oscillator range. The integer CPU mapping is only an emulator approximation of jointly drifting CPU/SysTick clocks; it does **not** prove each full simulated execution is a legal silicon schedule. A positive flip sensitive to CPU quantization is an artifact or unknown until independently validated. Do not use a flip from this arm alone to claim silicon timing brittleness.

## Versions, screening, capture, and analysis

Before any perturbed run, screen every version at 100 MIPS, nominal 16 MHz in **five fresh Renode processes**. The selected upstream case must pass in each run; unrelated ztest cases and skips are reported separately. For each generated suite, keep its original Phase 2 build and source judgment, but require a new 5/5 nominal pass and `functional=met` under the [split-gate protocol](../../analysis/PHASE2_SPLIT_GATE_PROTOCOL.md) for the primary timing denominator. The original strict oracle gate is recomputed as a secondary result. A nominal screen failure remains in the generation inventory and is never silently replaced. The Luna HSI inventory has 34 amended-functionally-eligible sources before this new screen; the upstream candidate inventory is the ten previously nominally passing Phase 1 HSI applications. The unregistered Sol feasibility pilot is excluded. Future Sol and Astra cohorts use the identical task manifest, generation protocol, screen, and saved HSI schedule after a separate user review.

Each eligible version then runs all 100 seeds and both endpoints in fresh processes with frozen source and full ELF. Save source/ELF/platform hashes, exact frequency and MIPS setting, Zephyr commit, Renode version, quantum, seed, UART/monitor logs, and virtual-time trace. Replay every pass-to-fail assertion from the same inputs, compare sampled traces, and apply the four-way classification: brittle test assumption, firmware bug, simulator artifact, or unknown. Preserve harness errors as non-evaluable and keep them in denominator accounting. Report flips/evaluable seeds with Wilson intervals **per suite**, task-stratified paired comparisons, and endpoint outcomes separately. Do not treat five generations of one task or repeated schedule seeds as independent firmware subjects; report the task structure and uncertainty. RQ1 source judgment is independent of observed flips. No repair is in this arm.

The arm may begin only after the registered RTC workers finish, to avoid concurrent Renode load and the already observed monitor startup error. This scheduling decision changes no RTC record or plan.
