# Registered Phase 3 RTC schedule arm

Registered 2026-09-29 before any Phase 3 agent timing run. This arm is independent of the unresolved HSI/CPU-coupling choice. The selected upstream Zephyr RTC callback case and two **nominally passing but oracle-inadequate** frozen agent suites are retained as three distinct test versions. The latter are the primary Luna `rtc_alarm_callback-r04` (15 s calendar arrival cap) and separate bound-informed supplement `rtc_alarm_callback-r05` (`K_NO_WAIT` for callback two). No RTC agent suite passed both nominal and source-oracle gates, so these agent runs are **exploratory RQ2 timing-flip measurements**, never counted as oracle-adequate robustness successes. Do not pool their generation denominators or treat them as independent firmware subjects. All nominal failures, unknowns, and negative results stay visible.

## Legal input and schedule distribution

Use pinned Zephyr v4.3.0 commit `3568e1b6d5cdd51a6b964a2a1d6d29200fea2056`, STM32F4 Discovery STM32F407VG, Renode 1.17.0, 16 MIPS CPU, 16 MHz SysTick, and 1 µs quantum. Vary **only** Renode's STM32F4 RTC `wakeupTimerFrequency` within 17,000–47,000 Hz; nominal is 32,000 Hz. [STM32F407 DS8626 Rev 12 Table 35](https://www.st.com/resource/en/datasheet/stm32f407ig.pdf) gives that LSI range at VDD = 3 V over ambient −40 to 105 °C. The [pinned STM32 RTC driver](../../subjects/upstream/zephyr/drivers/rtc/rtc_ll_stm32.c) sets a 128 × 250 prescaler. The [Renode RTC model](https://github.com/renode/renode-infrastructure/blob/master/src/Emulator/Peripherals/Peripherals/Timers/STM32F4_RTC.cs) accepts an RTC input frequency separately from CPU/SysTick. Do not infer an ISR latency bound from the LSI range. The model and environmental limitations remain in [THREATS.md](../../paper/THREATS.md).

Primary schedule IDs are seeds **0–99**, with each integer frequency `random.Random(seed).randint(17000, 47000)`. The same saved 100-frequency list must be applied to all three frozen ELFs. Exact endpoints 17,000 and 47,000 Hz are challenge runs **outside** the seeded-rate denominator. No perturbation bound is chosen in response to an observed agent flip. The earlier 30-seed upstream Phase 1 data remain separate historical evidence; rerun all 100 seeds here under one Phase 3 protocol for a direct paired table. A repeated nominal 32,000 Hz run tests host/harness stability, not schedule diversity.

## Eligibility, capture, and decision rules

First make **five fresh nominal repeats** of each frozen test version. Only a 5/5 passing version enters the conditional pass-to-fail numerator; any failure remains in the report and the 3-version inventory. A version that misses this filter can still be studied diagnostically, but it has no primary flip rate. Then run 100 seeds and both endpoints for each eligible version, with one fresh Renode process per run and no source or ELF changes. Record Zephyr commit, source and full-ELF hashes, exact platform hash/configuration, Renode version, seed, LSI frequency, virtual-time UART/monitor trace, verdict, and any timeout/harness error. Use the selected ztest case verdict, not unrelated full-suite cases. Every observed failure must be replayed in a fresh process with exact input hashes and sampled trace comparison; retain divergence as unknown. Preserve raw records without hand edits.

Per version report flips / 100 registered seeds, missing/harness-error/timeout separately, and a 95% Wilson interval for evaluable seeds. Report the 100 paired schedule outcomes side by side; paired disagreement counts matter more than comparing unpaired percentages. Frequencies are sampled units, **not** independent test authors, firmware projects, or physical chips. If repeated seeds yield duplicate frequencies, report the number of distinct configurations and do not treat duplicate deterministic replays as new schedule evidence. Endpoints are separate. Keep primary Luna and supplement labels separate; do not claim the supplement improved the original condition from these selected samples.

Apply the [four-way decision procedure](../../paper/DESIGN.md) to every nominal-pass-to-fail flip: brittle test assumption, genuine firmware race/bug, simulator/peripheral-model artifact, or unknown. Document the trace, source assertion, RTC calendar/peripheral state as needed, and why competing labels were ruled out. Hardware-bounded clock input alone does not prove that the model reproduces silicon callback timing. Classify conservatively where that matters; never silently remove unknowns. No repair belongs to this phase.
