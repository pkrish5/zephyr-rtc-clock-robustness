# Invalid nonfiring RTC mutant and proposed decision — 2026-10-06 UTC

The approved timing-quality arm registered three nominal-host fault operators per task. The first activation of the `never` operator used an effective `wakeupTimerFrequency: 1` in an isolated Renode STM32F4 platform while keeping CPU, SysTick, reference ELF, and nominal host setup fixed. Renode threw `System.DivideByZeroException` on the first 0.5-second `RunFor` call. The [activation record](../results/rtc_timing_mutants/activation_records/activation-rtc_time_counting-never.json) reports `harness_error` at virtual time zero; the [monitor log](../results/rtc_timing_mutants/activation_monitor/activation-rtc_time_counting-never.log) shows the model exception. No test verdict or mutant kill exists. The original platform, record, and manifest are preserved.

The 10-kHz `late` and 64-kHz `early` platforms activated their intended reference assertions in all three RTC task families. The late target would ideally arrive after 32 host seconds, beyond the 17-kHz legal slow bound of 18.823529 seconds; the early target arrives after five host seconds, before the 47-kHz fast bound of 6.808511 seconds (and the conservative 6.125-second early check). Their [raw activation records](../results/rtc_timing_mutants/activation_records) remain separate from suite scoring.

The [derived activation audit](../results/rtc_timing_mutants/activation_audit.json) checks all six expected reference assertion messages and platform hashes, confirms the 1-Hz model crash, and records `suite_scoring_authorized=false`. The mutant worker enforces that status.

The approved fallback rule says to report an invalid operator and seek review rather than replace it silently. Suite-level mutant scoring is paused. One small replacement candidate is a **1-kHz effective RTC clock**, which would need about 320 host seconds for the ten-calendar-second target, beyond the registered 70-virtual-second test window. It would be named **`windowed_nonarrival`**, since it suppresses the target only within the observation window, not forever. It may still expose a Renode model limitation; validate it against each reference task and inspect saved calendar/trace evidence before scoring. This would require a new operator/platform manifest and a versioned result namespace; it cannot be inserted into the existing 1-Hz records.

If a true stopped-clock mutant is required, an isolated RTC model or driver hook would need to freeze calendar progression after setup. That is more invasive, requires a new fidelity check, and has an unknown engineering duration. The alternative of scoring only the two validated operators yields an explicitly incomplete two-fault quality assessment. None of these options changes the legal LSI experiment or the original test ELFs.
# 2026-10-06 superseding decision

The user approved an interim score using only the six reference-validated early/late operators, now registered under `results/rtc_timing_mutants_two_faults/`. The earlier proposed 1 kHz windowed clock mutant is **not** being used. A new nominal-clock driver-path nonarrival operator is registered under `results/rtc_nonarrival_driver_v3/`: alarm callback/pending delivery is suppressed, or returned calendar progression is frozen for counting. All three task-specific reference tests must fail their named nonarrival-ceiling assertion before any eligible suite is scored on it. The 1 Hz crash and the two superseded pre-run engineering registrations remain preserved; none supplies a mutation kill.
