# IWDG configuration amendment — registered 2026-09-29 before a second build

The original upstream application configuration leaves `CONFIG_WDT_DISABLE_AT_BOOT` unset. On the selected STM32F407 IWDG driver, Zephyr's init path therefore installs and starts an initial 100 ms watchdog timeout. The unchanged upstream `test_wdt` then calls `wdt_install_timeout` for its own 2000 ms interval, but the driver returns an error because a reload value is already installed. The first [five raw probe records](../results/iwdg_fidelity/summary.json) are preserved: four immediate assertion failures and one Renode monitor harness error at virtual zero. They do not test reboot or `.noinit` retention.

For the *separate selected configuration*, add only the study-owned [`disable_at_boot.conf`](../subjects/iwdg_fidelity/disable_at_boot.conf) with `CONFIG_WDT_DISABLE_AT_BOOT=y`. This is a supported Zephyr configuration, keeps upstream C source untouched, and allows the test to install its own timeout before starting the watchdog. Build a new ELF and freeze it separately from the first ELF. Re-run the same prespecified three nominal 32 kHz probes and 17/47 kHz endpoint probes with the same simulator settings and pass criteria from `IWDG_FIDELITY_PROTOCOL.md`. Record both configurations in the report; do not reinterpret or delete the first failures. This selection is a compatibility fix made after observing the first configuration's failure, so disclose it and do not present the second configuration as the sole preregistered IWDG result.
