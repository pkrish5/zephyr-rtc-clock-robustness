# STM32 IWDG reset-state model validation — registered 2026-09-29

This is a **separate feasibility task**, not admission to the study corpus. The user asked to validate Renode's watchdog reset state and propose IWDG for review only if it passes. Use pinned Zephyr v4.3.0 `tests/drivers/watchdog/wdt_basic_api` unchanged on STM32F4 Discovery, with its upstream `boards/stm32_iwdg.overlay` and the study HSI overlay. Upstream Twister does not list this board for its STM32 IWDG configuration, so this is a study-selected build. Keep the source/ELF frozen across frequency probes.

The STM32F407 LSI range is 17–47 kHz at 3 V and −40 to 105 °C ([DS8626 Rev. 12, Table 35](https://www.st.com/resource/en/datasheet/stm32f407vg.pdf)). The [Renode STM32F4 platform](https://github.com/renode/renode/blob/master/platforms/cpus/stm32f4.repl) instantiates `STM32_IndependentWatchdog` at 32 kHz; the [model implementation](https://github.com/renode/renode-infrastructure/blob/master/src/Emulator/Peripherals/Peripherals/Timers/STM32_IndependentWatchdog.cs) uses that frequency and requests a machine reset on timeout. The model has TODOs for reset-cause signaling and debug stop. Neither endpoint proves physical-board fidelity.

Freeze source, overlay, build command/log, and full ELF hashes. Probe nominal 32 kHz in **three fresh processes**, then exact 17 and 47 kHz inputs once each, at 16 MIPS CPU, 16 MHz SysTick, 1 µs quantum, and 250 ms observation step. Preserve complete UART, monitor, virtual-time trace, frequency, simulator version and hashes. Use a 30 virtual-second cap.

**Pass criteria before proposing corpus admission:** at all three nominal runs, the unchanged test reaches `Waiting to restart MCU`, the watchdog triggers a *reboot* without a new Renode process, the `.noinit` state survives so the second boot executes the `Testcase passed` branch, and the selected `wdt_basic_test_suite.test_wdt` eventually passes. Endpoint runs must also reboot/pass and show reset arrival ordered by frequency (47 kHz faster than 17 kHz), with no unexplained peripheral/model errors. A failure is retained and means IWDG is **not** proposed as a qualified study subject. Even if these checks pass, the missing reset-cause model and physical validation remain explicit threats; the user must review a proposed IWDG addition before its task enters any generation list.

The STM32 IWDG driver rejects callbacks (`-ENOTSUP`) and the test verifies reset with retained RAM, so it would be an adjacent watchdog-timing stratum, not an ISR-callback subject. The Zephyr driver computes reload from nominal `LSI_VALUE`; any endpoint timing difference can implicate driver behavior as well as test assumptions and must be classified accordingly in later experiments.
