## Source mechanism and deadlines

The upstream case requests a two-tick relative alarm and busy-waits `1.5 * counter_ticks_to_us(dev, ticks)`, or 3,000,000 microseconds (3 s) on the nominal 1-Hz RTC-only counter. The driver adds one compensating tick for a partially started tick. Delivery can need two to three physical RTC ticks; at the 17-kHz legal endpoint, three ticks ideally require `3 * 32000 / 17000 = 5.647059` independent seconds. Source-based phase envelope is `21.333–32.000 kHz` for the original 3-s wait, not a single threshold. The full-application phase has not been directly measured.

The deadline values below are fixed *before* new execution. They are not fitted to a fault result. The 2-s allowance is inherited from the earlier E repair arm as an **experimental** allowance, not a certified interrupt/service-latency bound. The 13-s ceiling is inherited from the earlier S2 counter reference protocol (`ceil(4 * 32000 / 17000 + 5)`), deliberately conservative and not claimed optimal. The reference's 5-s allowance and extra uncertainty tick are not a hardware guarantee.

| Variant | Registered intervention at the one upstream wait site | Meaning |
| --- | --- | --- |
| V0 | Original source and existing full-application legal verdicts. | Baseline; new fault probes use original source. |
| V1 | Replace only the selected case's 3-s `k_busy_wait` with `k_busy_wait(13000000)` (13 s). | Deliberately naive long extension, retaining wait style. |
| V1b | Replace the same wait with `k_busy_wait(7648000)` (7.648 s). | Counter-derived three-tick legal endpoint plus the prior 2-s experimental margin, rounded up to a millisecond. |
| V2 | Use a 7,648-ms uptime deadline and 20-ms `k_msleep` polling of the original non-destructive callback count; retain the original final callback-count assertion. | Event/state waiting under the same ceiling. Do not consume the semaphore. |

V2 begins its uptime budget immediately before waiting, after alarm setup, as V0 does. It stops when the original expected count arrives or the ceiling expires, then executes the original count assertion. All channel setup, unsupported-channel checks, cancellation, teardown, original callback implementation, and all other test cases stay unchanged. V3 is **not applicable** in this extension: the prior V3 specification and alarm-calendar offset operator do not transfer to this relative-counter case. A new counter-specific oracle or offset operator would require a separate, prior registration and activation check; do not silently append one here.

## Execution order, outcomes, and controls

1. Seal this protocol and validate the exact source substitutions before any variant generation. Generate V1/V1b/V2 in fresh paths and record original/variant SHA-256, diff, source-site count, and assertion-retention checks. No source adjustment after a gate or varied-clock outcome.
2. Build one full F4 counter application per new variant with the pinned S2 configuration and simulator. Require five fresh nominal 32-kHz launches per variant, with complete full-application case verdicts and `test_all_channels` passing before its legal schedule. A build failure, missing case, nominal selected-case assertion failure, or harness error is a retained variant failure/unknown; do not retry until it passes or alter the source in place.
3. For every nominal-qualified variant, run the exact 100 pinned F4 seeded frequencies plus 17- and 47-kHz endpoints, fresh processes and unchanged ELF per variant. Report pass, selected-case assertion fail, skip, and missing separately, per frequency. No rerun fills an original missing result. Full-application vectors also track every other case and the later `test_single_shot_alarm_notop` outcome. A disappearing cascade is supported only when the repaired earlier case passes and the later case passes in that same run; it is not counted as another independent repaired wait.
4. At nominal clock, run 64-kHz fast and 10-kHz slow out-of-envelope oscillator probes for V0/V1/V1b/V2, each with the exact same case selection and fault activation record. Run a driver-path alarm-nonarrival probe only if an independent reference/control confirms its activation for the RTC-only counter; otherwise report it as not evaluable, not survived or killed. Calendar-alarm signed-second offset probes do not apply. A fault kill requires verified activation and an explicit selected-case assertion failure; a crash, timeout, skip, or absent verdict is missing. The 10-kHz relative alarm may arrive before V1b/V2's 7.648-s ceiling for some phases; fault preservation is an empirical question, not guaranteed by the deadline arithmetic.
5. Replay a small, fixed set of any *new* legal/fault assertion failure classes at the same exact input, keeping both original and replay records. Use task-specific passing references where available to distinguish premature assertion from an unresolved firmware/model contract. Replays and reference results never replace primary verdicts. Preserve control failures and investigate without changing frozen primary data.

## Analysis and stop rules

Primary legal outcome: per-variant pass/fail/missing over the 102 paired settings; report subject count as one, not 102 independent subjects. Fault outcome: selected-case fail/pass/missing for each activated operator and variant, including V0. Report each operator separately, not one pooled mutation score. Cascade outcome: paired earlier/later case status on the same full-application launch. Include host wall and virtual duration separately. Never interpret a missing verdict as a pass, fault kill, or repair success.

If a legal repair fails, a fault survives, or the cascade remains, report that result without redefining the study or tuning the margin. If the baseline, source hash, build configuration, simulator image, or controls do not match the pinned inputs, stop before production and preserve the failed attempt. A later engineering correction requires a separately dated amendment and new output namespace. The manuscript must not call this fourth case successfully repaired until its primary verdicts and fault records are verified.
