# Analysis

`phase0_summary.py` summarizes the feasibility fixture. `phase1_summary.py` validates the pinned Zephyr upstream-baseline records and computes suite and case flip rates with Wilson intervals. `phase1_lsi_rtc_summary.py` validates the separate, selected RTC alarm callback experiment and produces its Wilson interval and four-way classification table. `phase2_static_scan.py` finds source-level timing candidates in matched upstream cases and frozen agent suites; those candidates require manual judgment. `phase2_oracle_review.py` creates and validates the per-suite review checklist in `phase2_oracle_decisions_luna_primary.json`. `phase2_timing_examples.json` records selected manual judgments without claiming an exhaustive RQ1 numerator. `phase2_summary.py` audits generation, build, nominal, and review hashes and reports attrition and token use. Perturbed-schedule comparison and repair analyses begin only after the corresponding phase reviews.

The 2026-09-29 oracle amendment is specified in [`PHASE2_SPLIT_GATE_PROTOCOL.md`](PHASE2_SPLIT_GATE_PROTOCOL.md). `phase2_split_gate.py` audits frozen sources and reports the original strict and amended functional attrition separately. `phase3_rq1_review.py` maintains the one-reviewer source ledger; [`blind_rq1/PACKET.md`](blind_rq1/PACKET.md) and `make_blind_rq1_packet.py` provide 12 anonymous code items for independent user review. After all labels are entered in `blind_rq1/labels.csv`, `rq1_kappa.py` reports the three-category confusion table and Cohen's kappa; it refuses incomplete labels. `phase3_hsi_plan.py` and `cross_model_lock.py` audit the registered 100 MIPS HSI inputs and Luna/Sol/Astra comparison lock. `phase3_rtc_summary.py` audits the ongoing RTC raw artifacts and now reports eligibility under both oracle gates without changing the original RTC run plan.
