# Proposed protocol amendment: documented timing ranges in generation context

**Drafted 2026-10-01; approved and adopted 2026-10-03 before any Sol/Astra generation.** This draft records the decision provenance. The implementation and exact prompt/order lock are versioned separately in `generated/spec_context_factorial_v1/` so the earlier 13-task lock remains immutable. The independent RQ1 labels are a separate agreement analysis and do not alter this generation factor.

## Factor and comparison

For each of the 13 frozen tasks, generate five independent suites per model and prompt condition: Luna, Sol, and Astra × **documented timing ranges absent/present**. Keep behavior specification, production-code excerpt, API signatures, required functional oracles, output schema, generation tool, and nominal build settings identical within a task. The present condition may state only the cited, task-relevant hardware timing range and its environmental qualifier: e.g., STM32F407 HSI 16 MHz ±1% at 25 °C for HSI tasks, or LSI 17–47 kHz at 3 V and −40 to 105 °C plus the fixed RTC prescaler for LSI tasks. It must distinguish a clock bound from any undocumented ISR-to-thread latency guarantee. Do not expose upstream test source, observed flips, or a suggested test repair. Save exact prompt bytes, model identifier and available version, date, tool version, raw response, tokens, and source hash for every call.

Register the two prompt variants and their hashes before calling any model. Interleave the two conditions within each model/task using a saved random order, hold the same `k=5` per cell, and use separate generation outputs as the unit. Keep the original and amended source gates: build/nominal/functionally adequate is the primary timing filter; timing-bound adequacy is a measured source outcome; the original strict gate is secondary. Freeze every suite before schedules. Compare (1) functional adequacy and timing-bound adequacy by prompt condition, (2) conditional seeded flip rates on the same legal schedules, and (3) model × context interaction. Use task-stratified, paired schedule reporting; do not count the five generations or 100 seeds as independent firmware subjects. Retain failures, uncertain source judgments, and harness errors.

The earlier five-suite RTC bound-context supplement is exploratory: it differs in API hints as well as clock context and cannot serve as a clean factor cell. The one-suite Sol feasibility sample is excluded. The existing 65 Luna no-range generations provide a historical comparison but were created earlier and partly with a different CLI prompt transport. A clean factorial estimate therefore requires **390 fresh calls** (3 models × 13 tasks × 2 conditions × 5 outputs), with the old Luna and supplement cohorts reported separately. A cheaper reuse option would require 325 new calls, but time/provider drift and transport differences would confound the Luna context contrast; it should not be presented as the preregistered primary factorial comparison. This proposal adds no task or hardware condition and does not alter the already running RTC/HSI data.

## Provisional resource estimate

The 65 completed Luna task-generation calls reported 901,914 input tokens, including 639,744 cached, and 39,115 output tokens. At those observed means, 390 calls would use approximately **5.41 million input tokens** (3.84 million cached if caching repeats) and **235,000 output tokens**. This is a planning estimate; model-dependent reasoning tokens, output length, cache behavior, rate limits, and retries could change it substantially. It excludes build/simulation compute and any stalled calls with unreported usage. A fully eligible design could require up to 39,780 seeded/endpoint Renode runs (390 suites × 102 settings), plus nominal screening; actual totals depend on attrition and should be budgeted before approval.

At the [OpenAI API standard short-context token prices published on 2026-10-01](https://developers.openai.com/api/docs/pricing?tab=suite), applying the observed Luna token mix to 130 calls per model gives an **illustrative API-equivalent** total of about **$12.63** with the same cache hit rate, or **$26.56** with no cache discount (Luna $0.10/$0.01/$0.50, Sol $2/$0.20/$10, Astra $10/$1/$50 per million uncached input/cached input/output tokens). The existing authenticated Codex CLI does not report billed API dollars, so these figures are **not** a charge estimate for the actual route; record its real token/cost metadata where available. Simulator wall time and manual source review are likely the dominant costs. Re-estimate from the first balanced cell before committing to the remaining calls, without modifying registered comparisons in response to outcomes.
